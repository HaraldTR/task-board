Spaces: the context layer above projects

Linear's hierarchy is Workspace → Team → Project → Issue. This maps it onto the vault: the vault is the workspace, spaces are your teams (citadel, personal), projects nest inside them as folders, and tasks stay flat — inheriting their space through their project.

Projects get physical folder grouping by space — the parent folder is the space, so it can never dangle or typo. Tasks stay flat: they change status constantly and derive space via project:, so the board always sees everything and space filtering costs nothing.

06Introducing it — the migration, in order

  1. Create spaces citadel and personal (notes + space folders + catch-all projects) — done by code, one command.
  2. Re-point tasks: every task with project: citadel → citadel-general, personal → personal-general. The old citadel/personal pseudo-project folders (if any) are absorbed.
  3. Move existing real projects (test-project, szechuan-sauce, morty…) into their space folder — you assign each via one dialog pass, or drag folders in the file explorer.
  4. Peel projects out of the catch-alls at your leisure — select a batch of citadel-general tasks, give them a real project. The catch-all shrinking toward zero is the health metric.
  5. Anything space-less stays visible: projects not yet inside a space folder show under an “unspaced” group in the overview until you file them.

Everything above is additive to the current data model — no task frontmatter changes at all (space is derived), projects only change path. The plugin's rename/archive machinery already moves folders safely, so the space layer rides on code paths that exist today.
